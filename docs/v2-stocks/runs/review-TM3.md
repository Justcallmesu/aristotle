**MAJOR-1 (Back from news loops), AristotleApp.kt:272-274, 293, 397-399.** Path: Home → News (newsFrom=Sessions) → tap stock A (stockFrom=StocksNews, newsFrom=Sessions) → "All news" (newsFrom=StockDetail). Back gives A, then Back gives News (stockFrom), then Back gives A again (newsFrom is still StockDetail), and so on forever. `BackHandler` stays enabled because page != Sessions, so neither Back nor the top-bar arrow can ever reach Home. Fix: when leaving StockDetail back to News, reset newsFrom to Sessions (or keep a real stack). Test this sequence through the state holders, not only the pure `backFrom`.
**MAJOR-2 (1.3x fit drops every time label), PriceChart.kt:200-202, 338, 395-396.** `chartHeight` adds `14 × fontScale` dp to 234, but the labels are measured with the real style:
- Compose applies non-linear font scaling on every API level (`AndroidDensity` → `FontScaleConverterFactory`, active from ≥1.03). Its 1.3 table maps 14sp to 18.8dp, and 11sp to 14.3dp; the Atkinson ascent+descent is 1.3em, so a label is ≈18.6dp.
- `chartAxis` is also `.scaled()` by the in-app text size (Large = 1.15, Theme.kt:28).
Results:
- System 1.3x: label 18.6-18.8 dp, but the room is 234 + 18.2 = 252.2 dp, so `fitsBelow` fails for every label.
- In-app Large at system 1.0x: label 16.1-16.4 dp, but the box stays at 250 dp, so every label is dropped there too.
- Before this change the labels overflowed by about 0.1-2.6 dp and were still drawn. Now the time axis vanishes in exactly the case the ticket targets.
- `ChartFitTest` cannot catch this: it reuses the same linear 14 × scale arithmetic.
Fix: size the box from the measured axis line height (`TextMeasurer`/`LocalDensity`, which includes the app scale and the non-linear converter), plus a 1 px slack for rounding. Add a test at app scale 1.15 and font scale 1.3 using the non-linear value.

Only the 12:00 and Fri 11:30 cases are really fixed.
