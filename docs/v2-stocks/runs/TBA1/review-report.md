## Findings
- **MAJOR-1 (test-only; required by the PM): no test checks that the scheduled brief never runs on a weekend or holiday (Q108).** The only weekend check is `POST /brief` → 422 (tba1_test.go:667-668). I re-applied the PM mutation (`TradingDays: false` at stocks.go:159) on scratch: every existing test passes. My scratch test kills it.
  - **Test shape** (`TestBriefNeverOnWeekendOrHoliday`), with `newBriefHarness` at Fri 2026-11-06 17:00: (a) assert `briefJob().next_run` = `2026-11-09T08:30:00+07:00` (cheap, cannot hang); (b) `tickAt` Sat 11-07, Sun 11-08 and holiday 2026-12-25, each at 08:30:05, then expect `fa` opened = 0, `GET /brief?date=2026-11-07` → 404 `no_brief`, no `brief` alert, and job `last_due` not on those days; (c) use a bounded `waitFor`, not a bare `sched.wait()`: under the mutant my version hung until the test timeout instead of failing cleanly. Same gap, lower stakes (no AI spent): the `news` and `alerts` jobs have no weekend test either.
- **MINOR-2: the no-prices rule (`priceLike`, brief.go:771-789) has two holes and refuses legit text.** Probes: `"support di 2050"` passes (a bare 1990-2099 counts as a year, and many IDX prices sit in that band); `"4,9 ribu"` passes; `"volume 150%"` and `"MA200"` are refused. Fix: accept a year only next to a year word, a month or `Q1-4`/`FY`; accept a number followed by `%`/`persen`; refuse `<n> ribu|rb|k`.
- **MINOR-3: a setup first logged by a re-rank never alerts that day.** The hits dedupe (date, code, setup, dir) ignores origin. After a mid-day settings PUT, the same setup from the next scan is not logged again, so it gets no setup alert and does not count towards Q107. Fix: let a scan/eod fire "upgrade" a rerank-only key.
- **MINOR-4: the auto-run cap is not safe when `stocks-alerts.json` is unusable.** With `persist=false` (alerts.go:118-121) the counter lives in memory and every restart allows 5 more runs. Suggest: no automatic runs while the counter cannot be saved. Related: a clock that jumps back across midnight and forward again also resets it (a nit).
- **MINOR-5: the brief retries a dropped mid-turn socket.** `hermes_lost` is retryable (brief.go:270). A drop after `prompt.submit` has already spent an Opus turn, and each retry opens a fresh session, up to about 6 by 09:00. Retry only when the failure happened before the submit (Check or Open).
- **Nits:** (1) The server does not compare the snapshot's `info.model` with the pinned Sonnet: if Hermes ignored the pin, the run would silently go to Opus, and only `result.model` would show it. (2) A retry woken after a suspend can run after 09:00 (no cutoff re-check after `b.after`). (3) §20.4 says the 503s are "checked first", but the code checks `not_trading_day` before Hermes; the `hermes_lost` retries are not documented. (4) `canonical_sessions.py` is cited as :29 in three places; it is :28. (5) `PUT /holdings` without `stop`/`target` clears them: documented, but TBA2 must always resend them. (6) A refused auto run (`busy` when 3+ codes qualify at once) is dropped, not queued.
VERDICT: CHANGES-REQUIRED (MAJOR-1 only: add the weekend/holiday brief test; the code itself is correct; MINOR-2..5 optional)
