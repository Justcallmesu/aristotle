**MAJOR-1 (Q106): a watchlist/holding row hides a bearish flag whenever the same code is also a candidate.** `SetupLabels.forCode` (`ScreenerLogic.kt:105-109`) returns the candidate row and never merges the flag row. The server puts one code in both lists when bullish and bearish setups fire together (`screener_setups.go:342-361`), e.g. a gap down on a volume spike (sell-off day) or an MA cross down with an RSI rebound. The rows show one label (`StocksHome.kt:257`, `StocksPages.kt:212`, `max = 1`), so a held LQ45 stock on a sell-off shows a neutral "Vol ×2,3" and no gap-down label. The only places it is visible are the page's "Your stocks · bearish" list. The test `ScreenerLogicTest.kt:61-66` encodes this behaviour.
Fix: for own rows, merge the candidate's and the flag's setups, bearish labels first (so the one visible slot or "+N" covers it). Add a fixture with one code in both `candidates` and `flags`.
