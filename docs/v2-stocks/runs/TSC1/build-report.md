# TSC1 build report: scheduler, bar store, universe override, jobs API

- **Scheduler** (`server/internal/stocks/scheduler.go`): reads the wall clock every 30 s (WIB, IDX calendar). Supports "at" jobs and interval jobs that run inside windows. A job never runs twice at once. Other tickets add jobs through `sched.register(JobSpec)`. Q31 catch-up: only the latest slot counts. On time = within 2 min. `bars.daily` always catches up. Other "at" jobs run late until 16:00 of their day, else they are recorded `missed`. Interval jobs only resume (no burst). State is in `stocks-jobs.json`: settings set by PUT, the `handled` date, and the last due/run/status/error/late. A bad file is left alone: defaults run and PUT answers 500 `state_error`. The scheduler starts only from `Serve` (`server.stocksJobs`), so app tests never call Yahoo.
- **Bar store** (`bars.go`, P8): `stocks-bars.json` holds completed daily bars. Caps: 300 bars and 400 days per code, 400 codes, 32 MiB. A corrupt file means an empty store plus a log line. `bars.daily` runs at 16:20 on trading days over universe ∪ watchlist ∪ holdings. Codes go oldest-fetched first, one `1y` chart each via the new `Market.ChartFresh` (no cache, shared backoff), 1.5 s apart. A block stops the run; the partial store is saved and the next day resumes with what was left. A full run prunes codes that left the set. The file is written once per run. The analyzer preflight now uses `dailyBars`: the store when it was fetched at or after 16:15 of the previous trading day, else Yahoo as before.
- **Universe** (`universe_override.go`): an optional `stocks-universe.json` with LQ45/IDX80 lists, `valid_to` and optional `valid_from`. It is validated, and a bad file falls back to the bundled list with `file_error:"invalid"`. Routes: `GET/PUT/DELETE /v1/stocks/universe` (codes `^[A-Z]{4}$`, 1-200 distinct, body ≤ 16 KiB). The universe sits behind an atomic pointer. Names and search stay bundled; `in_universe` follows the list in use.
- **Jobs API**: `GET /v1/stocks/jobs` and `PUT /v1/stocks/jobs/{id}`. `at` is 05:00-23:00, `every_min` is 5-30, fields only per `editable`. Errors: 404 `unknown_job`, 400 `bad_request`.
- **Docs**: protocol §20.2 added. The §20 sentence "Yahoo only when a phone asks" now also names the bars job. CHANGELOG has one Server line at the top of Added.
- **Deviations from TSC0 design**: the job id is `bars.daily` (per the brief). The bars job always fetches `1y`: a 5d daily range is not in `ChartRanges`, and the call count is the same. There is no Saturday reseed. `auto_runs` is left to TBA1. `DELETE /v1/stocks/universe` was added (reset to bundled). Settings live in `stocks-jobs.json`, as in design §2; `stocks.json` is not changed.
- **Tests** (fakes only): `scheduler_test.go` covers on time, Fri→Mon, holidays, suspend jumps, restarts, off/on, time edit, interval with Friday windows, no overlap, panic, stored settings and HTTP. `bars_test.go` covers fill, prune, reload, Monday partial-bar drop, block/resume, failed codes, corrupt file, caps, freshness and `ChartFresh`. `universe_override_test.go` is new.
- **Gate**: `GATE_ONLY=server gates.sh docs/v2-stocks/runs/TSC1` exits 0: gofmt, vet and tests pass, 577 passed, 0 failed. `go test -race ./internal/stocks/...` is ok.
