**Findings** (none BLOCKER/MAJOR)
- MINOR (TS2b): a check that never calls back still suppresses locking. While `authenticating > 0`, a return is only stored (`AppLock.kt:54-57`) and judged when the check ends. The RESUMED guard closes the known cause, but the brief's "never-returning check no longer suppresses" is not literally met. The test `aCheckThatNeverEnds…` calls `authEnded`, so it does not prove the claim. Fix: cap it, e.g. ignore a check that started more than about 2 min before the return.
- MINOR (TS2b, device): FLAG_SECURE added in `onPause` (`MainActivity.kt:86-91`) may reach WindowManager after the API 29-32 task snapshot. That is unverified. The fallback is to keep the flag on the whole time the lock is on, below 33. Also, on API 29 the PIN activity stops MainActivity, so with "Immediately" a cancelled fresh check (Terminal, Always allow) locks the whole app. That is fail-safe; noting it.
- MINOR (TV1b/D48): `ServerVersions` is not keyed by PC. `record` runs on OkHttp's callback thread even after the caller is cancelled (`ServerClient.kt:129`, `execute` at `:151-170`), so a late `/v1/me` from the old PC can land after `clear()`. The reverse can also happen: in `replace`, `clear()` runs after the commit and the disk IO (`PcRecords.kt:43-44`), so it can wipe the new PC's first record, which hides the banner until the next connect. The impact is display only and it heals on reconnect. Fix: `record(pcId, …)` and ignore a record whose pcId is not the active PC.
- MINOR (TV2, changelog accuracy): `CHANGELOG.md:36` "Announce itself … so a phone can find it": the phone side (TL1) is TODO, so no shipped app can find it. Reword, e.g. "(the app uses this in a later version)", or drop the clause. `:44` "fingerprint, face or screen lock": on 30+ the check is BIOMETRIC_STRONG only, so most face unlock (including the Poco's) does not qualify. Say "fingerprint or screen lock".
- MINOR (TQ2/Q59): Q59 says "first open **or after a reconnect**". `feed.loaded` never goes back to false (`ChatFeed.kt:146`, copies elsewhere) and the effect is `LaunchedEffect(Unit)`, so no quote ever shows after a reconnect. The PM should decide whether Q44's reconnect screen covers this, then amend Q59 or build it.
- MINOR (design): `CompatibilityBanner.kt:34` uses `errorContainer`. design.md §5 says banners use `surfaceContainerHighest` with `onSurface` text. `ui/sessions/WhatsNewCard.kt:26` uses `surfaceContainerHigh`, but cards use `surfaceContainerLow`. design.md does not mention either new element.
- NIT: opening What's new from About does not dismiss the card (`AristotleApp.kt:274`), which contradicts `WhatsNew.kt:9` "Opening the page … records". Rotating while a chat loads picks a new inline quote. The overlay's M3 Surface swallows taps for at most 1.6 s after load (acceptable per Q59's ≥1.2 s). The generator would leak wrapped Server-bullet lines and `[x]: url` link refs (`build.gradle.kts:39`). The About value repeats "PC server". The board's TV1 row is still TODO though TV1a and TV1b are DONE. ChatScreen's new imports sit above the existing block.

VERDICT: PASS-WITH-FINDINGS
