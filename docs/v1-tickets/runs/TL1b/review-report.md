# TL1a+TL1b re-review — server mDNS responder (security)

**Method.** I wrote my own probe (scratch `tl1b-probe/`: `ns.sh`, `drv.py`, `cmd/mdnsprobe`). It runs the real `discovery.MDNSStart` inside `unshare -rn` with a peer netns and three veth pairs: lanA 192.168.50.10/24, lan2A 192.168.60.10/24, and tsA 100.64.0.5/24 + fd7a::5. The responder ran on lanA and lan2A. `rp_filter` was set to 0, so only the responder's own checks were tested. An avahi-like wildcard socket was joined on tsA and lanA for the whole run, and AF_PACKET sniffers on the peer side recorded every 5353 packet. Nothing ran on a real NIC, and port 8760 was never used. `go vet ./...` and `go test -race` on discovery/app/listen/config pass, and `TestNamespaceResponderStaysOnLAN` RAN and passed. hashicorp/mdns and miekg/dns are gone from go.mod/go.sum.
**MAJOR-1 is closed** (probe evidence):
- `ss` shows only `224.0.0.251%lanA:5353` and `224.0.0.251%lan2A:5353`. Nothing is on 0.0.0.0, `/proc/net/udp6` has no 5353 entry, and our sockets are gone after Stop.
- **No answer** to: unicast to 192.168.50.10:5353 (from port 5353 or an ephemeral port), unicast or legacy to the Tailscale address 100.64.0.5, multicast QM or legacy on tsB (avahi socket joined on tsA), tsB with a spoofed LAN source 192.168.50.30, an off-link source 10.9.9.9 on lanB (QM and legacy), and IPv6 unicast to fd7a::5 or ff02::fb on tsB and lanB. The tsB sniffer saw zero packets from us during the whole run, including announcements and goodbyes.
- **Answered correctly:** a QM query on lanB gets a multicast reply on lanB only (PTR plus SRV/TXT/A, IP TTL 255, A=192.168.50.10). A query on lan2B gets a reply on lan2B only, with A=192.168.60.10, so the interfaces do not cross-talk. A QU query gets a unicast reply to the asker. `aristotle-probehost.local` A is answered; `probehost.local` gets nothing, so avahi's name is not claimed.
**Raw socket code (`socket_linux.go`).**
- Setup order is correct: REUSEADDR, REUSEPORT, IP_MULTICAST_ALL=0 and BINDTODEVICE before bind, then bind to the group. Every error path closes the fd; `FilePacketConn` dups the fd and the deferred close releases the `os.File`.
- No fd leak: 300 start/stop cycles plus 300 failing starts leave the fd count at 4→6. The +2 is the runtime poller (1 cycle gives the same 4→6).
- A group bind makes the kernel pick the source address by route; replies came from 192.168.50.10, sport 5353.
- **SO_BINDTODEVICE needs no capability on Linux ≥5.7**: the responder started under `setpriv` with CapEff and CapBnd at 0. On kernels below 5.7 it returns EPERM, which is warned once and retried with backoff, not silent.
**Lifecycle, RFC behaviour and the old minors.**
- On the wire: two announcements per interface 1 s apart; TTLs PTR/TXT 4500, SRV/A 120, cache-flush on unique records; goodbye TTL 0 on both interfaces at Stop; legacy replies echo ID and questions, TTL ≤10, no cache-flush, from port 5353; rate limit: 10 QM queries in 0.5 s → exactly 1 multicast reply.
- Restart loop: `Sync` runs on every 10 s reconcile, stops a responder whose `Err()` is set, and backs off 10 s→5 min with one warning per distinct error. Shutdown path: `Manager.Close`→`OnChange(nil)`→`Close`→goodbye.
- Old minors: m1 closed (on-link askers only; unicast to our addresses is unreachable). m2 and m4 closed. m3 closed apart from probing, conflict resolution and known-answer suppression, which §15 documents.
- §15 matches the code. No other wildcard bind in `server/`: the loopback listener is validated to 127.0.0.1 or ::1, the LAN/TS TCP listeners bind a specific address with a device pin, and the control socket is a unix socket.
**Hostile input.** 3009 hostile or fuzzed on-link packets caused no panic, and the responder still answered afterwards. They covered compression self- and 2-cycle loops, counts of 65535, empty and 5-byte packets, a 30 KB datagram (truncated at the 9000 B buffer), opcode 15, and responses. `go test -fuzz` on `decide`+`pack` (scratch copy) ran 60 s and 362k execs without a crash.
**MINOR**
- **n1 CPU cost per packet is uncapped.** A 9 KB query with 1494 compressed questions costs 14–70 ms in `decide` on this machine (it was under load average 17). `allQU` re-runs `answer` once per question, which makes the QU path the slow one. A legacy query of that kind is echoed as an 8595 B reply to a 8433 B query: about 1:1, on-link only. An on-link flood can pin one core per interface. Suggest dropping queries with more than ~32 questions.
- **n2 Stale ifindex.** If an interface is deleted and recreated between scans with the same name and addresses, the responder keeps the stale ifindex and BINDTODEVICE and goes silently deaf until something changes. It fails closed; only availability is affected.

VERDICT: PASS-WITH-FINDINGS
