**MINOR-1 (D35 duplicates the running prompt after a steer).** `withRunningPrompt` compares only the history's last user row (`ChatReducer.kt:110,114`). Hermes stores a steer as its own `role:user` row mid-turn (`agent/agent_runtime_helpers.py:3705-3721`, `prompt_builder.py:586-592`, `display_kind` steer). HistoryMapper renders every user row (`HistoryMapper.kt:25`).
So opening a chat (a full snapshot) mid-turn after any steer, the phone's or the Desktop's, appends the started prompt a second time, below the steer. It stays until the next full snapshot. The same happens when the stored content differs from the pending text (attachments → `[screenshot]`).
Fix: skip steer/`display_kind` rows when finding `lastUser`, and add a test.
**MINOR-2 (4409 can leave a background link down indefinitely).** After a 4409 no round runs until a network change, foreground or Retry (`LinkManager.kt:105,335`). With the app in the background on a stable network, approval notifications stop until the user opens the app.
D33 (one socket at a time, `:186-238`) already rules out the flip-flop the stand-down guards against. So a live-socket 4409 only comes from a race: a cancelled earlier attempt whose upgrade the server completed late. Fix: a slow backstop round (for example 60 s), or the normal backoff.
**MINOR-3 (Refused is broader than "surely not delivered").** Any JSON-RPC error makes a steer retryable. A `-32603` dispatch crash (`tui_gateway/ws.py:480-484`) or a STRICT ContractViolation from `check_result` after `method(text)` (`registry.py:106-107`) can follow delivery. Limit steer Retry to `code 4001`.
