**Findings (none blocking)**
- MINOR-1: The `cron.changed` refetch is not tied to the lifecycle (`CronViewModel.kt:269-284`). With the page left open in the background it still lists up to once every 2 s on each jobs.json move, and that file moves on scheduler ticks too (`change_watcher.py:375-377`). Also, resume does not refetch at once, so a sibling profile's list can be up to 20 s stale on return. The arm is reset, so this is not a safety issue.
- MINOR-2: The `scoped` proof is ignored. Hermes adds `scoped:<profile>` to show the scope was honoured, and says older gateways omit it (`methods_tools.py:1314-1317`). On such a gateway the phone would silently list and change the launch profile's jobs. Suggest: if `profile != null` and `scoped != profile`, warn and disable the controls.
- MINOR-3: Bot Mode never lets a legacy delegated `[bot:x]` routine resume: it auto-pauses it and disables its switch (`cron.tsx:99-103,133-160,499-500`). The phone's switch allows resume. The Desktop Cron page has no such guard either, so this is an edge case.
- NIT: "Schedule times are the PC's clock" — Hermes runs cron in its *configured* timezone (`jobs.py:820-828`), which can differ from the PC's system clock. The month day accepts 0 and 32-99, so only Hermes' refusal catches them. The Create arm is counted from when the form opens and does not re-arm when the refusal block moves the button down (`CronFormPage.kt:117-123`).
