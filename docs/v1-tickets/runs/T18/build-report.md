**Finding:** cron is **not** REST-only, and not all on `/api/ws` either. WS has `cron.manage` with five actions, which the Desktop's Bot Mode Routines pane uses. Edit, run now, run history and the full prompt exist only in the REST API used by the Desktop's Cron page. So I built the WS part and documented the REST part. I added no server proxy; that is the PM's call.

**Built (android/\*\*).** `data/cron/CronFrames.kt` builds the frames and maps lists and answers. `data/cron/CronSchedule.kt` turns schedule strings into words and picker choices into schedule strings, gives the next run in phone time, and flags overdue jobs with the Desktop's 15 min grace. `ui/cron/CronViewModel.kt` lists on each socket, after `cron.changed` (one refetch per 2 s window), every 20 s while the page is resumed, and after each action; the profile goes through `ProfileLink`. Every control is behind the 600 ms arm, and a refresh that flips a switch re-arms it, as does resume. Refusals, RPC errors, no answer and not sent are each reported; nothing is retried. `ui/cron/CronScreen.kt`, `CronFormPage.kt` and `CronText.kt` add the "Scheduled" page, opened from a new schedule icon in the sessions top bar. Each row shows the name; the schedule in words · next run (phone time) or Paused/Overdue; the last result (red only when it failed); and the switch. The detail page has the switch, Hermes' issue text, facts, a prompt preview with a note when it was cut, a PC-only note, and Delete with a confirmation, as on the Desktop Cron page (`app/cron/index.tsx:826-840`). The create form has the Desktop's picker plus Advanced, Stop after N and continuity, and shows Hermes' refusal text inline. `AristotleApp` gets a route with its own store, cleared on leave. EN/ID strings. `docs/protocol.md`: new §13; the wrong "REST only" line in §7 is corrected.

**Tests:** 29 new (`CronFramesTest` 9, `CronScheduleTest` 7, `CronViewModelTest` 13). They cover frame keys against `CronManageParams`, list/detail mapping, schedule display, the arm at 599/600 ms and after a flip or resume, delete confirm and cancel, create with a Hermes refusal and no retry, the `cron.changed` debounce, polling only while resumed, and offline. Mutations: removing the arm check fails 5 tests and removing the debounce window fails 1; both were restored (byte-compared).
