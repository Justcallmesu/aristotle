# TS1 build report — Settings screen

**Status:** built; android gate GREEN.

**Built (android only).** One Settings page from the sessions gear replaces T10's, grouped: Connection & PCs, Notifications, Appearance, Language, Security, About.
- **Connection & PCs** (`ui/settings/SettingsConnection.kt`, pure rules in `SettingsModel.kt`): PC named by its last working address (the protocol has no PC name); live link line; pinned fingerprint as the pairing 4×4 grid (`FingerprintGrid` now `internal`); addresses LAN then Tailscale, each kind's last working first and marked "worked last", the link's own marked "in use now"; Keep connected switch; **Pair again**; **Unpair** (AlertDialog, error-outlined confirm like Scheduled's Delete, shows the selectable `aristotle-server devices revoke <deviceId>`; the token is never shown).
- **Re-pair:** new `PairedPage.Repair` shows `PairScreen` with a `RepairMode` (back arrow, note with the revoke command for the old id). `PairViewModel` got a `savePairing` seam; re-pair passes `PcRecords.replace(old, new)` → `CredentialStore.save(new, replacing = old)` writes the new entry and makes it active, and only then removes the old one; after that the old PC's profile and pins go. Any failure (bad code, server error, Keystore) leaves the old pairing untouched. Drafts stay (same sessions, most likely the same PC).
- **Unpair:** `AppContainer.unpair` → `PcRecords.unpair`: credential entry + active pointer (token, pin, addresses), `ProfileSelection.forget`, `SessionPins.forget` (all profiles of that PC), `ChatDrafts.clear`. App-wide settings (theme etc.) stay.
- **Notifications:** `background/NotifyChannels.kt` `AppChannel` (same ids `link`/`turn_finished`/`needs_you`; Notifier uses it). Each row mirrors the system switch (read-only `Switch`, re-read on resume) and opens `ACTION_CHANNEL_NOTIFICATION_SETTINGS`, or the app's page while all notifications are off. Battery guide kept.
- **Appearance:** `ThemeChoice` System/Light/Dark and `TextSize` Small 0.9 / Default 1.0 / Large 1.15 in `AppSettings` (same prefs file, keys `theme`, `text_size`). `MainActivity` collects them: `AristotleTheme(darkTheme, textScale)` multiplies `LocalDensity.fontScale` (sp text only, phone scale kept, applies at once); bar icons follow the forced theme; new `LocalDarkTheme` used by the terminal palette.
- **Language:** platform `LocaleManager` on 13+, no AppCompat (AndroidX `AppCompatDelegate.setApplicationLocales` needs an `AppCompatActivity`/AppCompat theme below 13 — developer.android.com/guide/topics/resources/app-languages). Below 13: stored in `AppSettings` and applied in `MainActivity.attachBaseContext` + `recreate()`. `res/xml/locales_config.xml` (`en`, `in`) + `android:localeConfig`.
- **Security:** header + "App lock — Coming soon". **About:** name + line, version from `BuildConfig` (`buildConfig = true`), What's new / licences "Coming soon", source/author line.
- Strings EN + ID for all new copy; language names untranslatable in their own words.
