**TL2 privacy: no BLOCKER/MAJOR.** No path I could find puts a token, pairing code, secret, full fingerprint, content, title or path into the log or crash file. Every call site sends events, enums or counts: link state, cause/network, LAN counts, route mode, version. `AppLog` errors record the class name only. OkHttp/RPC exception text holds only the method and code. Release builds no longer write to logcat. Redaction checked against real data shapes: the pairing regex matches the server's alphabet exactly (no I/L/O/U). The 43-char token is caught by its key rule or by OPAQUE. Fingerprints keep 8 hex characters. URL queries are cut, and so is text after "JSON input:". Ring is 2×256 KB, rotated, with a 512-line drop-oldest queue and one daemon writer. The handler chains to the previous one (or halts), and `runCatching` covers OOM. The dialog is composed after the lock `return`, and a new process starts locked. FileProvider exposes `camera/` and `share/` only. All files are in noBackupFilesDir/cache, and the rules exclude every domain from cloud and device transfer. Unpair clears the log, queue, crash and share files.
- MINOR-1: a crash's exception message (redacted, ≤300 chars) is the one place content could still get in. A third-party exception that quotes its input (e.g. `NumberFormatException: For input string "…"`, a Markdown parser error) is not caught by key rules. Suggest keeping messages only for app-package or allow-listed classes and writing the class name for the rest.
- MINOR-2: `takeOffer()` runs in `Application.onCreate`, so a headless start uses up the offer. After a crash LinkService restarts sticky. If that process dies before the UI opens, the report is lost. Take the offer when the dialog first composes.
- NIT: `AppLogSourceGuardTest` only checks lines containing `AppLog.`, so it misses indirect lines (`linkLogLine`, `log = AppLog::d` in PcFinder/WifiWatch). All are clean today. Revoked→`forgetPc` does not clear the log (Unpair does).
- Worker's 6 readings: (1) offer once / stale dropped: OK, with MINOR-2 caveat. (2) Send deletes: OK. (3) Back = Dismiss: OK. (4) Unpair deletes a pending crash: correct (it holds old log lines). (5) No logcat in release: good. (6) over-redacts 8-char code-alphabet words like DEADBEEF: acceptable. Missed: an all-digit code (≈1e-4) is not redacted. That's fine because no code is logged.

**TM2: OK.** Steer only sets a `DraftEdit` (re-checked `steerAllowed` and the Busy, not-blocked, no-attachment, not-`/` rules) and never sends. Quote goes in at `selection.end`, keeps the draft, is applied once per id and survives rotation. Copy, Share and Select use the message text only (Markdown source for replies, stream cursor stripped). Code copy uses `CodeBlocks.extract`, which strips fences and the language tag. Step/tool `SelectionContainer`s are untouched. The subagent page has no host.
- MINOR-3: the `pointerInput(host, target)` key changes on every streamed token. That restarts the gesture, so a long-press on a reply that is still streaming may never fire. Use `rememberUpdatedState(target)` and key on `host`.
- Device check: long-pressing a link in a reply may open the sheet *and* the link on release (the child's click sees the unconsumed up first). Also: the user bubble lost inline selection (now done through Select text, as intended).
- MINOR-4: CHANGELOG has no `Phone:` lines for message actions or the debug log/crash screen (What's new is built from it). TR7 could add a "Changed" line.

**TR7: OK, follows §5.7.** Fractions are null-safe and clamped (better than the design's `used/total`, which can divide by zero). A null field hides its meter or tile, and uptime text shows if all three meters are null. Stale state uses `outline` bars and `onSurfaceVariant` values. Red appears only on the Hermes line and tile. Toggle is ≥48 dp with one sentence. Icons render recognisably at the Outlined-400 weight; `vpn_lock` is the roughest, acceptable.
- NIT: CPU value reuses `pc_battery_value`. Address tile is not Mono 500 as the board shows. The red Hermes line also shows on stale (offline) values. No Compose UI test (no setup).

**TP1a/b/c: OK.** `GET /v1/pc-status` is mounted only on the remote router behind `requireDevice`. It is read-only, with no new listener and no wildcard bind. The sampler starts on demand and stops 60 s idle; TP1c makes the test deterministic (-race ×50). Hermes `Identify` every 10 s is one unix-socket round trip with a 2 s cap, plus a profile scan when down; that cost is negligible. A 5 s cache is optional.
- MINOR-5: after >60 s away from Home, the first poll gets `cpu_percent: null`, so the CPU meter vanishes for 10 s and the layout jumps. Fix either side: the server waits ≤1 s for the first pair, or the phone keeps the last CPU value or re-reads after ~1.5 s.
- `disk.path` = `/home/<user>`: acceptable, since the paired device already has terminal/Hermes access as that user. But nothing reads it (the phone parser ignores it), so data minimisation says send `"~"`: §16, one line plus a test, NIT.
