## Fixes (review finding → change → test)
1. MAJOR addresses: `PcAddresses.merge` puts the fresh list first, then every known address the PC did not report (one per URL, the fresh entry wins). Cap is `MAX_STORED = 8`; the tail (unseen longest) is dropped first, and `typed` + `lastGood` are never dropped. New `PcCredentials.typed` / stored `typed` is set at pairing and taken from `base_urls` for T07c entries (null for T09 entries). `CredentialCodec.withLink` merges under the store lock and is written only when the entry changes. Tests: `LinkManagerTest.anAddressThePcDoesNotServeRightNowIsKeptForLater` (office/home end to end with the real store), `PcAddressesTest`, `CredentialStoreTest.rememberMerges…` / `…CappedButKeepsTheTypedAddress`.
2. Refresh no longer blocks the link: `ServerClient.execute` uses `enqueue` + `suspendCancellableCoroutine` (`call.cancel()` on cancellation). The refresh also runs detached in the link scope; `online()` cancels it without waiting. Tests: `aSlowAddressRefreshDoesNotDelayTheLoss` (thread-blocking fake: offline in under 1 s, was 4 s), `ServerClientTest.cancellingTheCallerAbandonsTheRequestAtOnce` (was 10 s).
3. `RelaySocket`: on collector cancel, an open socket gets `close(1000)` and an unopened one gets `cancel()`. New `RelayChannel.cancel()`, which the link calls on `RoundEnd.Switch`. Tests: `aSocketStillConnectingIsDroppedAtOnce`, `cancelDropsAnOpenSocketWithoutACloseFrame`, and Switch/not-cancelled cases in `LinkManagerTest`. Mutation check: putting back the plain `close()` fails the connecting test.
4. Errors: each round is wrapped. An unexpected exception becomes `Offline(AppError, "unexpected <Type>")` and the next round runs; the network collector is guarded too. `AppContainer`'s link scope gets a `CoroutineExceptionHandler` as the last guard (logs the type only). **Decision:** a failing store during the address refresh is best effort and does not end a working relay; ending it would reconnect about once a second. Tests: `aFailingStoreNeitherCrashesNorEndsTheLink`, `anUnexpectedErrorGoesOfflineAndTheNextRoundRuns` (no uncaught errors in either).
5. Network change: `NetworkSnapshot` now also holds `vpn` and every Wi-Fi/Ethernet link that is not a VPN, with its IPv4 set. It is fed by a second `registerNetworkCallback` (`onLinkPropertiesChanged`/`onLost`) and seeded from `allNetworks` (deprecated; suppressed) so start-up does not register as a change. So Wi-Fi→Wi-Fi under Tailscale emits, which evicts the pools and retries at once. Test: `NetworkSnapshotTest` (pure). The Android callback wiring itself has no unit test.
6. `sock_unix_test.go`: `waitUntilAWriteWaits` polls goroutine stacks until a `trackedConn.Write` is parked in `pollDesc.waitWrite` (EAGAIN), with a 10 s limit. It replaces the 200 ms sleep in the D27 test and the 50 ms sleep in the Close test. The 300 ms sleep in the first test stays: that test needs the peer's receive buffer full, not just the first EAGAIN (tried, and it fails). I could not make the old test flake under 12 busy processes.
7. NITs: "Tailscale may be off" only when `!vpnUp` (`LinkEnds.offline(…, vpnUp)` + tests). ID "Terakhir berjalan pukul". Offline title uses `tnum`. `runCatching` removed from the refresh and from `SessionRepository.runtime.describe` (catches `RpcException`/`IllegalArgumentException` only). `reached()` resets `failures` (test `hermesDownInBetweenResetsTheFailureCount`, was 3 not 1). Rows are live only while Online (`SessionsUiState.staleAt`, test). Banner status line is now "Reconnecting… try N" / "Reconnecting… try N, next in S s" (EN+ID, old `offline_trying`/plurals removed, new `offline_cause_app_error`). Also removed a duplicate `Icon` import.
