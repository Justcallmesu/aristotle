## 1. All running work in one screen
- No single global RPC. `agents.list` is blocked on the shared socket (`hermes/tui_gateway/ws_legacy_fallback.py:46`) (V). `delegation.status` returns every live subagent in the process with no profile filter and no processes (`hermes/tui_gateway/methods_session.py:2196-2201`) (V).
- `session.active_list {profile?}` lists the profile's live sessions with `status` = `working` (turn running), `waiting` (a prompt is open), `starting` or `idle`, plus `id, title, model, started_at, last_active, message_count, source` (`hermes/gateway/session_active_list.py:15-44`) (V). The Desktop polls it for its sidebar (same file, `:3-6`).
- `subagent.roster {profile?}` returns `{sessions:[{session_id, subagents, background}]}`: counts of top-level children and running background processes, keyed by STORED session id. No session needs to be attached (`hermes/tui_gateway/methods_subagents.py:66-83`, `:114-138`) (V). The Desktop reads it once per backend on connect and focus, then every 10 s while visible (`hermes/apps/desktop/src/app/contrib/hooks/use-live-work-roster.ts:72-81`, `:118`) (V). Its Agents panel combines live `subagent.*` events from every session (`hermes/apps/desktop/src/app/agents/index.tsx:89-98`) (V).
- Details per row: `process.list` / `subagent.list {session_id, profile}` need the session to be live in that authority, NOT resumed by this socket (`hermes/gateway/session_ancillary.py:226-241`, `hermes/gateway/session_authority.py:186-195`) (V).
- **Design:** `profiles.list` (already called: `aris/android/app/src/main/java/io/github/justcallmesu/aristotle/data/SessionRepository.kt:95`), then per profile `session.active_list` + `subagent.roster`, i.e. 2×P calls per refresh (P≈6 → 12 small in-memory/state.db reads). Run it every 10 s only while the screen is visible, and again on `sessions.changed`. Tapping a row → `process.list` / `subagent.list` for that session. Hermes needs no change.
- **Risks:** roster ids are stored/lineage ids, while live rows use session ids. The Desktop maps them with lineage aliases (`hermes/apps/desktop/src/store/live-work-roster.ts:5-14`), so the phone must match on both `id` and `resolved_id`. A background process whose session is no longer live is counted, but `process.list` answers `not_found`, so the phone cannot stop it (A: whether this happens in practice).

## 2. Usage / cost per session
- Stored per session in state.db: `input/output/cache_read/cache_write/reasoning_tokens`, `api_call_count`, `estimated_cost_usd`, `actual_cost_usd`, `cost_status`, `cost_source`, `pricing_version` (`hermes/hermes_state_common.py:485-507`). Per session×model in `session_model_usage` (`hermes/hermes_state_schema.py:78-98`). Each API call adds a priced delta (`hermes/agent/turn_usage.py:233-275`). The cost is COMPUTED from a pricing snapshot / models.dev table (`hermes/agent/usage_pricing.py:18-27`) with status `actual|estimated|included|unknown` (`:57-61`) (V). Units: tokens (int), USD (float). No per-turn rows found (A).
- Over WS: the resume/`session.info` snapshot `info.usage` and live `session.usage` events carry `{model, input, output, reasoning, prompt, completion, total, calls, context_used/max/percent, cache_hit_pct, avg_tps, compressions}`. These are cumulative for the session, with a stored-row fallback when no agent is loaded (`hermes/gateway/session_usage.py:130-159`, `:162-186`, `:217-227`) (V). **No cost on this path**: `Usage.cost_usd` exists in the contract (`hermes/tui_gateway/contracts/common.py:52-53`), but `tui_usage` never fills it (V). `session.stats` returns live counters only (`hermes/gateway/session_usage.py:230-239`).
- Cost over WS only through project-tree rows: `estimated_cost_usd`, `actual_cost_usd`, `input_tokens`, `output_tokens` per session (`hermes/tui_gateway/methods_projects.py:324-338`), and `totalTokens` / `totalCostUsd` per project (`hermes/tui_gateway/project_tree.py:350-367`) (V). Desktop: cost = actual, else estimated, and the cost sort is hidden when every cost is 0 because "subscription auth never quotes a price" (`hermes/apps/desktop/src/store/sidebar-archive.ts:140-148`) (V). The user's Claude OAuth runs are probably `included` → $0 (A).
- **Design:** the chat header shows the tokens and context % from `info.usage`, updated by `session.usage` events. The session list shows tokens and cost (only when > 0) from the §3 tree rows. No server change.

## 3. Projects: grouping and sorting like the Desktop
- A project is a per-profile row in `$HERMES_HOME/projects.db` with folders (`hermes/hermes_cli/projects_db.py:23-25`; `hermes/tui_gateway/contracts/projects_pets.py:20-48`). Sessions have NO project column. A session belongs to the project with the longest folder match on its `cwd` or `git_repo_root` (`hermes/tui_gateway/project_tree.py:337-346`). The tree has 4 tiers: Home bucket first, explicit projects, auto projects by git root, discovered repos (`hermes/tui_gateway/project_tree.py:445-501`) (V). A session's own project is also in the snapshot `info.project {id, slug, name, primary_path}` (`hermes/tui_gateway/contracts/common.py:57-63`, `:91`) (V).
- RPCs (sidecar fallback, profile-scoped, V): `projects.tree {profile, preview_limit?, session_limit?}` → `{projects:[{id, label, path, color, icon, isAuto, isNoProject, sessionCount, lastActive, totalTokens, totalCostUsd, previewSessions[], sessionIds[]}], active_id, scoped_session_ids}`. Drill-in: `projects.project_sessions {profile, project_id}` (`hermes/tui_gateway/contracts/projects_pets.py:263-304`; `hermes/tui_gateway/methods_config.py:137-163`). Cron, kanban and oneshot sessions and children are excluded (`hermes/tui_gateway/methods_projects.py:320-321`). `session_limit` defaults to 2000, so cap it on the phone. The `projects.changed` event means "refetch".
- Desktop sorting (all client-side, saved in localStorage, NOT on the gateway; `hermes/apps/desktop/src/lib/persisted.ts:74`):
  - Project order: Home, then the active explicit project, explicit before auto, projects with sessions first, then recency, then label (`hermes/apps/desktop/src/app/chat/sidebar/projects/model.ts:84-113`). The user can drag to override (`hermes/apps/desktop/src/store/layout.ts:154-161`).
  - Groupings: `date|project|status|profile` (`hermes/apps/desktop/src/store/layout.ts:275`). Sort keys: `updated|created|status|tokens|cost` (`hermes/apps/desktop/src/store/layout.ts:304`; `hermes/apps/desktop/src/store/sidebar-sort.ts:14-34`). Status rank: needs-input < working < unread < draft < idle (`hermes/apps/desktop/src/store/session-dot-state.ts:107-116`).
  - Pins: Desktop-local (`aris/docs/protocol.md:353-355`).
- **Design:** per profile `projects.tree` (preview_limit 3, session_limit ~300). Running state comes from `session.list` / §1. Copy the Desktop's sort rules on the phone, with phone-local order and pins. Hermes needs no change.

## 4. Clipboard to PC and back (aristotle-server only)
- Laptop (V, `command -v`, `systemctl --user show-environment`): KDE Plasma on Wayland. The systemd user manager has `WAYLAND_DISPLAY=wayland-0`, `DISPLAY=:1` and `DBUS_SESSION_BUS_ADDRESS` set. **`wl-copy`/`wl-paste`, `xclip` and `xsel` are NOT installed.** `qdbus6` is installed, and Klipper is on the session bus with `getClipboardContents` / `setClipboardContents(QString)`.
- T19c: the terminal removes desktop variables only from the SHELL child (`aris/server/internal/terminal/proc.go:105-113`; `aris/docs/terminal.md:59-62`). The server process keeps its own environment, so the two do not conflict. The doc already says a granted shell can read the clipboard (`aris/docs/terminal.md:12-16`).
- Risk: if the unit starts before Plasma has exported its env, the server has no `WAYLAND_DISPLAY`. Resolve it at call time from `$XDG_RUNTIME_DIR/wayland-*` (A).
- **Design:** REST `GET /v1/clipboard` (PC → phone) and `PUT /v1/clipboard` (phone → PC) behind `requireDevice`, following `aris/server/internal/httpapi/httpapi.go:93-105`. Permission: an off-by-default switch plus a per-device grant in its own state file, following the terminal grants (`aris/server/internal/terminal/grants.go:14-28`).
  - Limits: text/plain UTF-8 only, 256 KiB cap, read only on an explicit tap (no polling, no history on the server or the phone).
  - Logs: device, direction and byte count only, never the content.
  - Phone: set `ClipDescription.EXTRA_IS_SENSITIVE` (API 33+).
  - Backend options are in D4. Known gap: Klipper keeps every copy in its history unless the password-manager hint MIME type is offered (A).

## 5. Claude subscription limits ("session", "weekly", "Fable weekly")
- Hermes already fetches them (V): `GET https://api.anthropic.com/api/oauth/usage` with the user's Claude OAuth token. Mapped keys: `five_hour`→"Current session", `seven_day`→"Current week", `seven_day_opus`→"Opus week", `seven_day_sonnet`→"Sonnet week", using `utilization` (fraction → %) and `resets_at`, plus `extra_usage` credits (`hermes/agent/account_usage.py:844-871`, `:610-628`). It does NOT read the `anthropic-ratelimit-unified-*` headers: there is no match in the source, and the header tracker only knows `x-ratelimit-*` (`hermes/agent/rate_limit_tracker.py:1-6`).
- Exposed (V): `model.options` (already sent by the phone, `aris/android/app/src/main/java/io/github/justcallmesu/aristotle/data/chat/ControlFrames.kt:28`) attaches `providers[].usage.windows[{label, used_percent, resets_at, scope:"account"|"model"}]`, or `usage.accounts[]` for a credential pool. The values come from a cache, and each call starts a background refresh: the first call can come back empty, and data older than 15 min is dropped (`hermes/hermes_cli/inventory.py:292-357`; `hermes/agent/account_usage_cache.py:26-30`; `hermes/apps/shared/src/gateway-contract.generated.ts:879-890`). The Desktop shows them in its provider chip / model picker. `/usage` prints the same windows as text.
- **"Fable" gap:** Fable is a Claude model (`claude-fable-5-1`, `hermes/apps/desktop/src/lib/model-status-label.ts:114`). Hermes maps only the Opus and Sonnet weekly keys, so a Fable weekly window is DROPPED (V for the mapping). The exact API key name (e.g. `seven_day_fable`) is not known (A).
- **Design:** a phone "Claude limits" card reads `model.options` → provider `anthropic` `usage.windows`, with bars, reset times and a "refresh" button that calls again after 3 s. The Fable window needs D5.

## Decisions for the user
- **D1 Running-work scope.** (a) All profiles, phone fans out every 10 s while open (recommended: no server code, ~12 calls per tick); (b) only the current profile (cheaper, misses pm/default work); (c) one aristotle-server endpoint that fans out for the phone (one call, but new server code that duplicates Hermes logic).
- **D2 Cost display.** (a) Tokens always, $ only when > 0 (recommended; on subscription usage $ is 0); (b) tokens only; (c) $ always, showing "included" for a subscription.
- **D3 Grouping.** (a) Hermes `projects.tree`, same groups as the Desktop (recommended); (b) phone groups by `cwd` itself (diverges from the Desktop); (c) no projects, only date/status grouping + sort keys. Manual order and pins stay phone-local in all three (the Desktop keeps them in localStorage).
- **D4 Clipboard backend.** (a) Install `wl-clipboard` and use `wl-copy`/`wl-paste` (standard; needs a pacman install; Klipper data-control support A); (b) Klipper D-Bus (no install, text only, every phone copy lands in Klipper history); (c) (a) with (b) as fallback. Also: one global switch, or per-device grants like the terminal (recommended).
- **D5 Fable weekly.** (a) Ship with what Hermes maps (session + week + Opus/Sonnet), no Fable; (b) patch Hermes `_fetch_anthropic_account_usage` to map any `seven_day_*` key (a Hermes-side change, upstream or local); (c) aristotle-server calls `api/oauth/usage` itself with the token Hermes stores. **Flag:** that reads the user's Claude credential outside Hermes and spoofs a `claude-code` User-Agent like Hermes does. Not recommended.
