## Findings (no BLOCKER, no MAJOR)
- **M1 (MINOR) — hand-typed commands the Desktop refuses are sent.** These are commands with a non-null catalog `desktop`: `/footer`, `/verbose`, `/fast`, `/busy`, `/voice`, `/curator`, `/kanban`, `/insights`, `/toolsets`, `/platforms`, `/login`, `/clear`. The Desktop refuses them in the client (`desktop-slash-commands.ts:771-786`, `slash.ts:384-388`).
  The phone drops them from the catalog (`SlashCatalog.kt:66`), so `resolve` returns null and the command is sent (`SlashControl.kt:80-87`). The same happens for anything typed before the catalog loads. Hermes refuses or runs a reviewed handler, so nothing harmful happens, but `/busy` can change `busy_input_mode`, which design §5 says the phone never does.
  Fix: keep `commands[*].desktop` for every name and alias (the catalog keys aliases, `command_discovery.py:144`) and block typed commands where it is non-null (`hidden` `/model` → PhoneControl).
- **M2 (MINOR) — the confirm dialog has no staleness guard and no arming.** The Desktop drops the dialog when the model moves on while it is open (`use-model-controls.ts:412`). On the phone, if another viewer switches meanwhile and the guard no longer fires (`session_mutation_model.py:363-364`), "Switch anyway" applies over the newer pick.
  The dialog also appears asynchronously, yet "Switch anyway" is not armed for `ARM_MS` (`ModelSheet.kt:206-214`), unlike every other control in the project. The title shows the picked name; the parsed `target_model` is unused (`ControlFrames.kt:131`).
- **M3 (MINOR) — a skill or `send` id is minted after `slash.exec` answers (`ChatComposer.kt:44-48`).** The Desktop mints it before the call and reuses it when the same draft is retried (`slash.ts:251-271`).
  If a NoAnswer directive is dismissed, the field gets `/skill …` back (`ChatComposer.kt:132-141`). Sending that again runs a new `slash.exec` with a new id, which can start a second turn if the first submit had landed.
- **NIT:** `confirmation_required` without a token is read as Applied (`ControlFrames.kt:130-132`); Refused would be right. A blocked command clears the user's draft (`SlashControl.kt:81`). The open items in the build report are accurate.
