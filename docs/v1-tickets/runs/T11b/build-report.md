1. **MAJOR-1** (`ChatReducer.fromSnapshot`): on an omitted snapshot, `lastSeq`/`replayEpoch` come from the caught-up state. When the snapshot's `last_sequence` is ahead ("behind"), the turn, step and `running` state stay as they were caught up, and started admissions are not marked shown, because the frames in between finish the turn in place. Both info merges now run with `showStarted=false`. If the omit reply has a different `replay_epoch`, `ChatFeed` falls back to a full resume.
   - Tests: the misleading test now asserts `lastSeq == 11`. New tests: `framesHermesSendsBeforeAnsweringTheOmitResumeAreAppliedOnce` (the fake emits 11 again plus 12 before answering, then 13 arrives; result is "one two three"), `anOmitResumeOnANewEpochFallsBackToTheFullTranscript`, and the reducer tests `anOmittedSnapshotKeepsTheCaughtUpPosition…` (snapshot not running, delta + duplicate + complete arrive afterwards → one block) and `…AtTheCaughtUpPositionTakesItsRunningState`.
2. **D33** (`LinkManager.attempt`): on a switch, the open socket now gets a 1000 close (via the collector's `awaitClose`) instead of `cancel()`. A network change while a socket is still connecting ends that attempt at once (the connecting socket is cancelled) and restarts the round. Before, the attempt waited out the ready timeout and then switched away from a socket that had just opened. In every case the old socket ends before the next `openRelay`.
   - Tests: `aNetworkChangeWhileOnlineSwitchesToTheBetterAddress` (not cancelled, 0 sockets still active at the next open), `repeatedSwitchesKeepOneSocketAtATime` (L→T→L→T→L, one active at the end), `aNetworkChangeWhileConnectingDropsThatSocketAndStartsOver`. `RelaySocketTest.anOpenSocketWhoseCollectorGoesIsClosedWith1000` checks that the server receives the 1000 close frame.
