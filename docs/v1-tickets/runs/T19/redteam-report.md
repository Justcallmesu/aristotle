# T19 red-team report: remote-terminal design draft
Read: spec Q7c/Q7d/Q26/Q35/Q49/Q51, protocol §9, §11-§12, server `internal/{listen,httpapi,devices,control,config,app,service,relay}`, Desktop `electron/terminal-ipc.ts`. Paths below are under `server/internal/` unless they say otherwise. No code run.

## Answers to the draft's questions
- **Shell while disabled or ungranted / races:** the current code has no path, because there is no route: unknown `/v1/*` returns 404 (`httpapi/httpapi.go:82`). But the draft gives no mechanism. Config is read once at start (`app/serve.go:32`), the server never writes config, and there is a revoke hook (`devices/devices.go:180-196`) but no disable or ungrant hook. Auth runs before the upgrade (`httpapi/auth.go:17`), so a revoke or disable that lands between auth and spawn leaves a shell behind. The relay already solves this by registering first and then re-checking `Has` (`relay/relay.go:111-120`). The terminal must copy that pattern (see B1).
- **Token alone vs Q7c:** a lost unlocked phone already drives Hermes (spec.md:71, Q7c). The relay also passes `shell.exec` (no allowlist, spec.md:72). That is a filtered, 30 s, local-session-only shell (`~/.hermes/hermes-agent/gateway/session_shell.py:18,40,52`; that the phone's ticket passes `authorize` is ASSUMED). The terminal adds an unfiltered, interactive, long-lived shell as the same uid. The cheap mitigations each hold only until the first shell opens (B2).
- **Orphans:** killing the process group misses interactive bash's job-control jobs, which run in their own process groups, and anything started with `nohup`, `disown` or `setsid`. Survivors stay in the unit's cgroup. The unit sets no `KillMode` (`service/service.go:52-63`), so the default `control-group` applies: survivors die only when the service stops, restarts or crashes (`Restart=on-failure`, :57). Desktop has the same gap (`pty.kill()`, `terminal-ipc.ts:263`). See M1.
- **`yes` / `cat /dev/urandom`:** memory stays bounded if a single goroutine reads the PTY into a fixed buffer and does a blocking write (coder/websocket, `go.mod`). The real risks are elsewhere: a dead phone holds a never-idle shell (M2), and the phone could queue output without bound (M5). Use binary frames: random bytes are not valid UTF-8 text.
- **Sandbox:** `NoNewPrivileges=yes` (`service/service.go:59`) blocks setuid and file capabilities in every child: `sudo`, `su`, `pkexec`, `passwd`, `fusermount` (sshfs/rclone) all fail. `PrivateTmp=yes` (:60) means `tmux attach` and `/tmp/.X11-unix` don't see the desktop's `/tmp`; that it works in a user unit is ASSUMED. `UMask=0077` (:61) applies to the shell because `/etc/profile` sets no umask (VERIFIED by grep). So yes, the terminal must say so (see the D-sandbox decision).
- **Env leakage:** the server holds no Hermes secret in its env. It reads only `XDG_*`, `HOME` and `HERMES_HOME` (`config/config.go:262`, `hermes/hermes.go:114`), and the unit sets no `Environment=` (`service/service.go:45`). The shell inherits the user-manager env: `SSH_AUTH_SOCK` (the user's loaded SSH keys), `DBUS_*`, `INVOCATION_ID`, `JOURNAL_STREAM`, `MANAGERPID`. That env content is ASSUMED: the user bus was unreachable from here. Scrubbing env protects nothing a same-uid shell cannot read anyway (`~/.hermes/.env`, `tls-key.pem`). Strip the systemd vars, set `ARISTOTLE_TERMINAL=1` (like Desktop's marker, `terminal-ipc.ts:199`) and `TERM`/`COLORTERM`.
- **Logging:** the planned fields are safe. The request log writes only method, route pattern and status (`httpapi/logging.go:17,28`). The control log writes only `cmd` (`control/control.go:201`). Rules to add: never log a control-frame parse error with its text, never put the initial size in the query, and never log `$SHELL` or cwd. Two leaks are outside the logs: `~/.bash_history` keeps typed command lines, and on the phone, the recents snapshot and keyboard learning can capture content (M4).

## Findings
- **B1 BLOCKER: the switch and grant have no mechanism or ordering.** Store `enabled` and grants in a server-owned state file, e.g. `<state>/terminal.json` written atomically with statefile. Don't use config: it is static (`app/serve.go:32`), its keys are flat and strict (`config/config.go:103`), and its path is `config.json`, not `config` (:177). Don't use `devices.json` either: it is decoded with `DisallowUnknownFields` (`devices/devices.go:88`), so a new field means an older binary refuses to start. Fix the order: authenticate, upgrade, register in the terminal hub, re-check `Has && enabled && granted`, and only then spawn. Add OnDisable/OnUngrant hooks that close live sockets with a defined code, as 4401 does (protocol.md:605).
- **B2 BLOCKER: wrong threat model ("never toggleable from the phone").** The shell runs as the server's uid, so it passes the control socket's SO_PEERCRED check (`control/control.go:181-191`). From inside it, the phone can run `pair` (mint a token that outlives a revoke), grant itself, enable the terminal, or revoke the owner's phone. It can also copy `tls-key.pem` (`tlscert/tlscert.go:36`), which allows impersonating the PC after a revoke, and add `~/.ssh/authorized_keys`, crontab entries or user units. No same-uid check can fully stop this: `systemd-run --user` and editing rc files get around any check. The draft must say: terminal = full account access, and revoke is not cleanup. Write a lost-phone runbook: revoke all devices, delete the key pair and re-pair, check ssh keys, cron and units, rotate Hermes keys. Cheap partial fix: the control socket refuses `pair`, `grant` and `enable` from peers in a terminal's cgroup or session.
- **M1 MAJOR: process-group kill does not clean up.** Give each terminal its own cgroup and end it with `cgroup.kill`. One way is a transient user unit (`systemd-run --user --pty --collect`), which also takes the shell out from under NNP and PrivateTmp. Otherwise kill the whole session (`Setsid`) and record that `setsid`/`nohup` survivors last until the service restarts. Go caveat: `Pdeathsig` is tied to the OS thread.
- **M2 MAJOR: the draft names no keepalive.** Reuse the relay's ping (25 s) and close (15 s) liveness and `TCP_NOTSENT_LOWAT`. `Wrap` is set for the whole listener (`app/serve.go:97`), but the liveness logic lives in the relay session. Count idle time from input only: `top` or `tail -f` keeps a stolen phone's shell alive forever if output counts. Add a hard maximum session length. Without liveness, a half-dead socket after a Wi-Fi switch blocks the 2-per-device cap for minutes.
- **M3 MAJOR: limits copied from the relay would break typing.** 600 frames per 60 s (`relay/relay.go:22`) is about 10 keystrokes a second, and holding an arrow key would trip 4429. Use a byte-rate cap instead. Define pastes over 64 KiB as chunked by the phone, not closed with 1009. Clamp resize to 1..500. Desktop clamps only the minimum (`terminal-ipc.ts:373,474`), and the PTY winsize fields are uint16.
- **M4 MAJOR (phone): typed secrets reach the keyboard and screenshots.** Q51 already requires no suggestions plus FLAG_SECURE for sudo input (spec.md:118). Do the same here: `TYPE_NULL` or `VISIBLE_PASSWORD|NO_SUGGESTIONS` plus `IME_FLAG_NO_PERSONALIZED_LEARNING`, and FLAG_SECURE on by default (it also blocks the recents snapshot). What Termux's InputType does today is ASSUMED.
- **M5 MAJOR (phone):** OkHttp's `onMessage` must hand frames to a bounded queue with backpressure (protocol.md:645-647), or `cat /dev/urandom` exhausts phone memory and the UI thread.
- **m1 MINOR:** 403 already means "peer gate, use another address" (protocol.md:502-504). Make `terminal_disabled` and `terminal_not_granted` 403s with a JSON body, served after the 401 check, and update §11.2 so the phone does not switch addresses on them.
- **m2 MINOR:** `$SHELL` may be missing from the unit env (ASSUMED), and Go's `os/user` has no shell field, so parse `/etc/passwd`. Plain `/dev/ptmx` plus `syscall` ioctls is feasible without creack/pty. Linux only, with a `_other.go` stub as `control/peercred_other.go` does.
- **m3 MINOR:** the emulator should ignore OSC 52 clipboard writes and any query that answers back. Otherwise a file `cat`'d on the PC can write the phone's clipboard. Termux behaviour is ASSUMED. The Termux libraries' Apache-2.0 licence is ASSUMED, and they come from JitPack, so the user approves the dependency (PROJECT.md:45).
- **m4 MINOR:** a desktop notification when a terminal opens may have no session bus: the service runs under linger (VERIFIED `Linger=yes`) with no GUI session. Fallback: `aristotle-server status` lists open terminals, and the open/close lines go to the journal.

## USER decisions: one-line consequences
- Grant (a): an ungranted stolen phone gets no shell, but one extra PC command per phone. Grant (b): every paired phone is a shell, so pairing equals shell access.
- Reattach (a): simple, and no shell left unattended, but every network switch or app kill loses the shell's work. Reattach (b): work survives, but an unattended shell keeps running for N minutes, and the design needs ownership rules and a buffer.
- Idle 30 min (input-only, per M2): bounded exposure, and long `tail` sessions end. Longer or none: comfortable, but a lost phone keeps the shell open.
- FLAG_SECURE on: no screenshots or recents leak, and no screenshots for the user either. Off: terminal content reaches the recents snapshot and screenshots.
- New, D-sandbox (from M1/Q51). Child of the unit: sudo is impossible (also a safety net for a stolen phone), `/tmp` is private, umask 077. Transient user unit: sudo, tmux and `/tmp` behave as on the desktop, cgroup cleanup works, but a remote shell can become root if sudo is cached or the password is known.

VERDICT: READY-FOR-USER-DECISIONS. B1 and B2 are amendments to the draft, not a new architecture. Fold them in before tickets.
