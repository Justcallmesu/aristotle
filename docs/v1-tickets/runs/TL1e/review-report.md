Paths: `android/app/src/main/java/.../aristotle/` unless noted. LD = data/LanDiscovery.kt, ALD = data/AndroidLanDiscovery.kt, LM = data/LinkManager.kt.

## Previous findings: closed
- **MAJOR-2 is closed.** A refused bind now falls to `ScanGate.unbound` (LD:147-167). The unbound route is used only when the default network is a VPN over Wi-Fi alone (LD:163, ALD:98-110), the VPN has at least one IPv4 route (LD:164), and no route covers the network address, broadcast or first host (LD:92-103). The routes are read again on every search and before the scan (ALD:79-80, LD:433-441), and the mode is logged. The device fact matches: Tailscale ON gave "Found at 192.168.1.61". Tests: LanDiscoveryTest:290-379, 641-711.

- **NITs are closed.** NSD is scoped to the Wi-Fi network on API 33+ (ALD:208-213). A network wake ends the pending-trial wait (LM:426). Pre-34, a resolve that hits FAILURE_ALREADY_ACTIVE is retried 3x 500 ms (ALD:263-273).

## Unbound fallback: what holds
- **Per-target guard.** `reaches` (LD:42) runs before every socket: the probe at LD:450, the check at LD:470, and NSD addresses are on-link filtered first (LD:465). A VPN route that covers only part of the /24, missed by the 3 samples, is still skipped per target (test LD-Test:347, 641).
- **Route matching.** Longest prefix wins and a tie counts as covered (LD:86-88). A host that is not IPv4 counts as covered (LD:85). NSD passes on Inet4 only (ALD:295). On API 29-32 every route is unicast, which is safe because excludeRoute exists only from 33. On 33+, THROW is excluded. If a platform filters excluded routes out, the covering route remains, so the gate fails safe.
- **No name resolution.** `LiteralDns` (LD:119-124), the literal `inetAddress` (ServerAddress.kt:18-19) and the check's `dns(route.dns)` (ServerClient.kt:101-105) mean no DNS query is ever made. The check keeps the pinned client: NO_PROXY, no redirects, no token.
- **Other VPN setups.** A VPN over cellular, or over cellular plus Wi-Fi, gives Unavailable. A lockdown VPN gets netd's prohibit rule, so unbound probes fail closed and the user sees "Not found" (nothing leaks). The relay was already unbound, so this adds no new kind of egress.
- **Flap key.** It is the set of local network handles (data/NetworkWatch.kt:89). No SSID and no location permission are used (manifest has none). Memory is bounded: each call prunes, there are ≤3 timestamps per key, and a key exists only for an address that passed the pin and reached `ready`.
- **TS3.** While the app is locked, only `LockScreen` is composed (ui/AristotleApp.kt:74-81). `PairedPages`, its `BackHandler` (:244) and `SettingsRoute` do not exist then. The saved page comes back only inside `SaveableStateProvider` after unlock. A new process starts locked (data/AppLock.kt:43). No intent opens Settings. The back mapping (:185-193) is tested in PairedPageTest.

## Findings
- **MINOR-B: unbound sockets leave on the system default network, not provably on `wifi.handle`.** netd's VPN fall-through rule routes unrouted traffic to the system default network. The gate checks only that the VPN carries Wi-Fi alone (ALD:103-107); it never matches the VPN's network to this Wi-Fi. That gap matters in two cases: (a) two Wi-Fi networks are up (STA+STA local-only, or a hand-over; the watch picks the one "updated last", ALD:58); (b) a VPN pins its underlying network to this Wi-Fi while the system default is cellular (Wi-Fi without internet). Then up to 508 SYNs, plus pinned ClientHellos (IP literal, no SNI, no token), go to RFC1918 targets on another network. The pin holds, so only metadata leaks. Fix (small): on the unbound route, after connect require `socket.localAddress == link.address`, else close and count a miss, before any TLS byte.
- **MINOR-C: VPN routes are a snapshot for the whole search.** If the user turns an exit node on mid-scan, the remaining probes and checks enter the tunnel: about 5 s of /24 probing plus checks of up to 5 s each, or up to 10 s of the auto-find NSD window. This is bounded and pinned, with no token. Optional fix: read `access()` again every few batches, or cancel when the VPN's LinkProperties change.
- **NIT: RTN_UNREACHABLE is treated as "not covered" (ALD:120).** The kernel drops those packets; only THROW falls through. It fails closed, but the user sees "Not found" instead of "Can't scan" (for example, an IPv6-only VPN's 0/0 unreachable route).
- **NIT: the flap key is a set of handles.** Demotion resets on any reconnect, or when another local network comes or goes. An on-link attacker who can force a deauth can reset it, but that attacker can already cause a DoS.

Not verified: device behaviour of cases (a) and (b), lockdown, and the RouteInfo that Tailscale reports with an exit node.
VERDICT: PASS-WITH-FINDINGS
