# TL1e build report (MAJOR-2 discovery under Tailscale + MINOR-A + NITs)

Gate: `GATE_ONLY=android bash docs/v1-tickets/gates.sh docs/v1-tickets/runs/TL1e` → PASS android (exit 0; lintDebug, 831 unit tests, 0 failures, assembleDebug).

- **MAJOR-2:** `ScanGate.access(wifi, transports, bind, vpn)` (pure) now gives `WifiAccess.Unbound` when the bind is refused, the default network is a VPN over Wi-Fi only (no cellular or Ethernet transport), and `VpnRouting.coversSubnet` finds no VPN route for the Wi-Fi's network address, broadcast or first host. Matching is longest-prefix. On API 33+ RTN_THROW/UNREACHABLE routes count as excluded (`RouteInfo.type`). Routes with no IPv4 entry, or none at all, are treated as "can't tell". Covered subnet (full tunnel, exit node without LAN access, subnet router), VPN over cellular, no VPN → `Unavailable` ("Can't scan", auto-find skips). The unbound route uses plain `DirectSocketFactory()` and `LiteralDns` (IP literals only). It also carries the VPN routes: before every probe and `/healthz` check, `PcFinder` requires `route.reaches(host)` (on-link and not routed into the VPN). The NSD on-link filter and the pinned check are unchanged. Every search reads the routes again (`connectivity.activeNetwork` LinkProperties) and logs one debug line: `lan route: bound|unbound-vpn-no-route|unavailable`.
- **MINOR-A.1:** `onlineOn` records `trialFailedAt`. A 4409 that arrives within the ready timeout after a failed trial → `Switch` (new round), not a stand-down.
- **MINOR-A.2:** new pure `LanFlaps`. 3 post-ready losses of a LAN address within 5 min on the same Wi-Fi (`NetworkWatch.localNetworks()`, handles) demote it below Tailscale for 15 min, found candidates and trials included. A relay that comes up on an address that dropped within the window no longer resets the backoff. Tunables live in `LinkTimings`.
- **NITs:** NSD uses `discoverServices(type, proto, network, executor, listener)` on API 33+ (`ServiceBrowser.services(wifi)`). `endWhileTrying` now selects on the trial or a Network wake (no 20 s gap). Pre-34: a resolve refused with FAILURE_ALREADY_ACTIVE gets 2 more tries, 500 ms apart. The platform can't cancel the old resolve before 34, so this only helps when the old one answers late.
