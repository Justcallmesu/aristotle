# TF2 build report — D50, D53
Method: JUnitCore loop of the single test in one JVM (`Request.method`, fresh instance per run), 8 `yes` workers on 4 cores; workers stopped afterwards (`pgrep yes` = 0).
- **D50 RepairTest.successReplaces…** — cause (proven): test built `PcRecords(...)` with the default `io = Dispatchers.IO`; `replace()` runs `forgetSettings(old)` in `withContext(io)`, so on a worker thread while the Unconfined test thread went on to assert. Before: 67/300 failures, all `expected null, but was:<work>` at RepairTest.kt:137 (`settingsStore.get("profile.<old>")`), i.e. exactly the IO-hopped write. Fix: `io = Dispatchers.Unconfined` in the test. After: 0/300 under load.
- **D53 PcStatusPollerTest.readsEveryTenSeconds…** — cause (proven): the poller (Dispatchers.Default) does `reads += …` inside `read`, and only afterwards updates `view` and enters `pause`; the test polled `reads.size` (5 ms) and then asserted `pauses` / `view.fetchedAtMillis` / cpu, which are written later. Before: 3/300 failures, `expected:<11000> but was:<1000>` (view still the first round's). The `pauses == [10_000]` assert has the same window. Fix: the fake `pause` also signals a `paused` channel and the test awaits it (`awaitPause`, 5 s timeout) — a pause is entered only after its round's read and view update. Same swap in the other tests that assert the view after the first read. No bigger sleeps.
- Production code: no race (`PcStatusPoller`, `PcRecords` behave as designed); no production edits.
- After fix: 300/300 green each, under load. Files: `RepairTest.kt`, `PcStatusPollerTest.kt`, this report.
