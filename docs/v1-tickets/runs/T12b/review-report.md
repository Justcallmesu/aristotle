# T12b focused re-review: tap-through guard and the T12 minors (commit `0d9eddc`)
Scope: `git show 0d9eddc` (not the working tree), the T12 review, the T12b brief/report, spec Q50/Q51, and Hermes `gateway/session_server_requests.py` and `session_clarify_lock.py`. No gradle. Took the PM gate-20 result (281 tests, GREEN) and the arm-check mutation (7 tests fail) as given.
**1. Every answer path is arm-checked: PASS.** `send` is private. Its only callers are `choose`, `confirmAlways`, `answerClarify`, `answerSecret` and `declineSecret`, and each starts with `armed(...)` (`ChatViewModel.kt:104-141`). Arming is keyed by prompt key and step, so a stale `p1` lambda after the sheet swaps is dropped. `confirmAlways` also needs `confirmAlways == key` and has its own 600 ms window (`PromptSheetState.kt:70-85`). Clarify rows and the free-text field only edit the draft. Only the Answer button sends (`PromptSheet.kt:284`). A dropped sudo Send/Cancel does not run `field.take()`, so the typed value stays. Notification: `FLAG_IMMUTABLE`, no actions. It only reaches `openSheet()`, which re-tracks. The only state write that bypasses `track` is the `armed` flag flip (`:227`), which is UI-only. The ViewModel re-checks the time itself.
**2. Clock: PASS.** The default is `System.nanoTime()/1e6` (monotonic). Wall clock appears only in the countdown display.
**3. MINOR-1 cannot double-send: PASS.** `sending` gates a second send. After a refusal or a partial batch, the re-sent `clarify.lock` just overwrites the earlier lock ("editable until the last lock", `lock_answer:149-168`). A sudo/secret re-answer after a reconnect is a no-op if Hermes already resolved the id (`resolve` returns False on an unknown id, `:83-86`).
**4. Non-exported alias: PASS.** The alias has `exported="false"` and no intent-filter, and a manifest test checks both. MainActivity has only MAIN/LAUNCHER. For an external start through the exported entry, the delivered component is MainActivity. Another app cannot name the alias (SecurityException), so the `component == ALIAS` check holds. The PendingIntent is immutable.
**5. Profile + session matching: PASS.** In the single-profile case, every claim (ChatFeed and the watcher) is `Ref(null, id)`, so `requestFor` holds whenever the socket resumed the session. A prompt dropped during a replay-gap release comes back through the re-resume `open_requests`.
**MINOR-A (dead buttons in the confirm step).** While the "Always allow" confirmation is open, Deny and Allow once stay visible and enable after 600 ms. The ViewModel drops them because `choose` checks `confirming=false` against `Shown.confirming=true`. This fails safe, but a tapped Deny does nothing silently. Fix: disable or hide them in the confirm step, or have `choose` clear `confirmAlways` and re-arm.
**MINOR-B (armed while not visible).** Arming starts when the ViewModel state changes, not when the user can see the sheet. A prompt that arrives while the activity is stopped (background or screen off) is already armed on return, for example through the notification tap. Low tap-through risk: the return is deliberate, and the notification sits at the top while the buttons are at the bottom. Fix: re-arm (reset `shown`) on `ON_RESUME`.
**NIT.** After a reconnect, a sudo/secret prompt Hermes already resolved can look answerable again until the new snapshot arrives. A re-send is harmless but sends the password out again. A recents relaunch of a task the notification started re-delivers the alias intent; ignore `FLAG_ACTIVITY_LAUNCHED_FROM_HISTORY`. Alias delivery via `onNewIntent` still needs phone QA, as the build report says.
VERDICT: PASS-WITH-FINDINGS
