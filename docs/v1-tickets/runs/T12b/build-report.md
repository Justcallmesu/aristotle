**MAJOR-1 (tap-through).** `PromptSheetState.shown = Shown(key, confirming, at, armed)` is set by `PromptSheetLogic.track` whenever what the sheet has on screen changes: a new current prompt, sheet raised, withdrawn sheet closed, or the "Always allow" confirm step shown or cancelled. `at` comes from the injectable `ChatViewModel(clock=…)` (monotonic by default). Every state change goes through `ChatViewModel.change`, which re-tracks.
`choose`, `confirmAlways`, `answerClarify`, `answerSecret` and `declineSecret` are dropped unless `PromptSheetLogic.armed(...)` holds: that key, in that step, on screen for `ARM_MS = 600` ms. A dropped sudo tap leaves the typed value in the field.
The VM flips `shown.armed` after 600 ms. Until then the sheet's answer buttons are disabled; inputs stay usable. The confirm step has its own 600 ms window, so a double tap cannot turn "Always allow" into the confirmation.
Tests: two queued prompts, Once then an immediate Once → exactly one frame (a stale `p1` lambda is dropped too). A prompt arriving at t is ignored at t+599 and sent at t+600. Raising the sheet from the chip arms it again. Sudo Send/Cancel are ignored until seen. The buttons come on by themselves.

**MINOR-1 (dead chip).** `Refused` removes the key from `answered`, so the prompt is answerable again while Hermes lists it. If it is settled later, the sheet says "Answered elsewhere". Bare sudo/secret responses (no reply) are recorded in `unconfirmed` with their link generation. On a newer `Online` generation, `onReconnect` forgets them, and the new snapshot decides: answerable again, or closed/"Answered elsewhere". The waiting chip now shows only when `sheet.current(chat) != null`, so tapping it always opens something. 3 VM tests + 1 logic test.
