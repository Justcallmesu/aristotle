# UP2c build report: stale install statuses + check-time MINOR
- MAJOR: `AppUpdates` keeps the current install's session id (memory `session` + store key `update_install_session_id`, set via `UpdateDevice.install(file, onSession)` right after `createSession`, before commit). `UpdateInstallReceiver` reads `EXTRA_SESSION_ID`, asks `acceptsStatus(id)` (same session AND still Installing/Confirming) and otherwise logs one line (`update: dropped a stale install status=N`) and returns. `installFinished(outcome, sessionId)` re-checks.
- `giveUp` clears the session id first, then `device.abandon(id)` (new `UpdateDevice.abandon`), so the abandoned session's own Aborted status is dropped. `start()` clears the stored id. A late pending-user-action after give-up is no longer stored in `PendingConfirm` (the receiver returns before that).
- MINOR: `lastCheck` is stamped only after an answer (Available/UpToDate), so a failed or cut-off check does not block the next on-connect check.
- NIT: the KDoc "from the second self-update on" now says a self-update qualifies from the first one. The `install.sh` version-code NIT is out of scope (`android/**` only).
- Tests (RED first: 4 failed on the first run, before the fix): stale Aborted while Installing is dropped; the reviewer's probe scenario (give-up, Try again, stale Aborted arrives during commit, then pending-user-action) ends in Confirming with 1 confirm launch and the give-up abandons its session; late pending after give-up shows nothing; failed check and cut-off check do not block the next on-connect check, an answered one does. Existing tests now pass session ids.
- Gate after last edit: `GATE_ONLY=android bash docs/v1-tickets/gates.sh docs/release/runs/UP2c` exit 0 (PASS android, licences). Not verified on a device (no adb).
