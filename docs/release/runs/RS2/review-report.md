## Findings — RS2 (D45)
- **MAJOR-1 (completeness):** `okhttp-android` 5.4.0 bundles `assets/PublicSuffixDatabase.list`, the Mozilla Public Suffix List, under MPL-2.0. It is in `app-debug.apk` but not in `licences.json`. MPL-2.0 §3.2 requires telling recipients where the source form is. The generator only sees the classpath plus the fonts, so third-party data embedded in AARs cannot show up. Fix: add a fixed entry next to `bundledFonts` ("Public Suffix List (bundled by OkHttp)", MPL-2.0, https://publicsuffix.org/list/) and add `mpl-2.0.txt`. Optional: make `licencesCheck` fail on an unknown non-class asset inside an AAR (today only this file would trip it). Must be done before any APK leaves this PC (RS4).
- MINOR-2: nothing runs `--check` automatically: it is not in `gates.sh` and not in the build. Any dependency bump leaves the notices stale without anyone noticing. Fix: add it to the android gate or to RS4 `release.sh` (it runs from cache in about 25 s).
- MINOR-3: `LicencesScreen.kt:71` calls `Licences.detail(..., source.read)` during composition, so it reads asset files on the main thread on every recomposition, with nothing remembered. Fix: load the detail in `produceState(openKey)` on `Dispatchers.IO`.
- MINOR-4 (shape): `android/build.gradle.kts` applies the generator to `:app` with `project(":app") { apply(from = …) }`. That is cross-project configuration, used to get around a `lintAnalyzeDebug` crash whose cause was never found. The tasks also read `project.configurations`/`dependencies` at execution time, which breaks once configuration cache is on. Not fragile today: resolution happens only in `doLast`, so the order of plugin evaluation does not matter. Record the crash cause, or move the generator to an included build later.
- NIT: `noticeOf` only looks for a NOTICE at the outer zip's root or in `META-INF/`, not inside an AAR's `classes.jar` (none exist today). `licenceIdOf` maps any licence name containing "apache" (Apache 1.1 included) to apache-2.0. Copyright lines are made up per group prefix, not read from the artifacts.
- NIT (step 2 audit, Q129): `assets/quotes.json` has no credit line. Its Greek comes from Perseus canonical-greekLit TEI (CC BY-SA markup), and the Ross 1908 translation is public domain in the US only. These are short attributed quotations, so this is probably fine.
- Forward to RS4: `server/THIRD_PARTY_NOTICES.txt` must ship in `dist/` next to the binary (BSD-3 clause 2).

## Findings — RS3 (D31)
- MINOR-5: a failed restart after the unit was rewritten and enabled returns only `error: systemctl restart: exit status 1` (probe: unit written, `Restarted=false`). A restart is stop then start, so the server is now probably down, and the message neither says the unit was replaced nor where to look. Fix: say "unit written and enabled; restart failed: …; see `aristotle-server logs`".
- MINOR-6 (forward to RS4): `status` exits 1 until the control socket is up, so right after an `install --force` restart it can fail briefly. `install.sh` must poll `status` with a timeout rather than run it once under `set -e`.
- NIT: the `is-active` check followed by `restart` is check-then-act. `systemctl --user try-restart` does "restart only if running" in one step. An `activating` unit (crash-loop auto-restart) is not restarted, and the CLI then prints "The service was not running", which is wrong. The daemon-reload still takes effect on its next auto-restart.
- NIT: a unit path that is a symlink to a directory is refused with a raw `read …: is a directory` error that does not name the target. That is because the `!ErrNotExist` case comes before `linked` (`service.go:152`); nothing is damaged. A symlinked unit directory gets the file written into the link's target (probe), which is reasonable but undocumented.
- NIT (tests): `TestStatusExitCode` swaps the global `queryStatus` without `t.Cleanup`. Setup errors from `MkdirAll`/`WriteFile`/`Symlink` are ignored in the new tests.

VERDICT: PASS-WITH-FINDINGS (no BLOCKER; MAJOR-1, the MPL-2.0 Public Suffix List missing from the notices, must be fixed before RS4 builds a bundle)
