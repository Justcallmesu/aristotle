# UP2b build report: updater fix round
- MAJOR-1: manifest declares `UPDATE_PACKAGES_WITHOUT_USER_ACTION`; `UpdaterManifestTest` reads the source manifest and fails without it. Android docs (PackageInstaller.SessionParams#setRequireUserAction, reference page) list it as one condition; the others still apply: the installer is the app itself (self-update qualifies from the first OTA on), `USER_ACTION_NOT_REQUIRED` is set, API 31+ (phone is API 34). The reference page was only partly readable through my fetch tool, so the exact full condition list is ASSUMED from the review's quote. Q133 on HyperOS still needs the UP0 spike re-run (no adb here).
- MAJOR-2: new step `Confirming`. A `STATUS_PENDING_USER_ACTION` screen is held (`PendingConfirm`), shown at once, shown again 1 s after the app comes to the front (`AppContainer` watches `appVisible`; the 1 s lets the screen's own Cancel status arrive first) and by a new "Confirm install" button. An install with no status, or an unanswered confirmation, ends after 2 min with "Android did not finish the install. Tap Try again" (`InstallNotFinished`); the offer stays, so Update is never blocked. A status after that is ignored. The next install abandons our stale sessions.
- MINORs: Update claims `Downloading` before launch (double tap = one run); `checking` reset in `finally` (disconnect); on-connect check at most once per PC per 10 min (`checkOnConnect`; Check now and the 6 h loop ignore it); a checksum mismatch drops the offer and re-checks (row offers the new release or Check now).
- Restart (FGS rule, docs "Restrictions on starting a foreground service from the background"): `ACTION_MY_PACKAGE_REPLACED` is an exemption, so a non-exported `PackageReplacedReceiver` calls `BackgroundController.resumeAfterUpdate()` (starts `LinkService` when Keep connected is on). No notification fallback needed. The string now says: reconnects by itself when "Keep connected in background" is on (EN+ID).
- NITs: APK versionCode must equal the announced `version_code` (`WrongVersion`, EN+ID string); renamed Go test to `TestAppUpdateLogsOneLinePerDamagedRequest` (rename only, the one `server/**` edit; logging unchanged).
- install.sh: an APK in the bundle must have a version in its name and its own `SHA256SUMS` line, checked in `verify_bundle` before anything is touched; the app pair is now copied BEFORE the server binary, so a failed copy leaves the old server and a new server never lacks its pair. `install_test.sh`: 3 new cases (unlisted APK, bad name, unwritable app dir leaves old binary), RED first.
- Android tests (written first; green): AppUpdatesTest 25 (+12), ApkCheckTest 7, AppUpdateRulesTest 12, UpdateRowLogicTest, UpdaterManifestTest 2. Not verified on a device.
