## Findings
- MINOR-1 (install.sh, attack b): when run from the app's remote terminal, the shell lives in the unit's delegated cgroup. The restart kills it, so install.sh dies after the binary swap and before the poll; systemd still finishes the restart job. Every open phone terminal (and its processes) is killed on any update. If the new binary crashes, the user is locked out until he is at the PC. Fix: refuse when `ARISTOTLE_TERMINAL` is set or `/proc/self/cgroup` names the unit ("run it in a terminal on the PC"), and say in the README that an update closes the phone terminals.
- MINOR-2 (install.sh): when `install --force --start` fails (e.g. restart failure, after `.prev` was written), the script exits 1 with no rollback line and no journal tail (probe C). The poll timeout prints both. Fix: one `on_failure` helper for both paths, which also removes the duplicated rollback string at lines 76/117. No test covers this path.
- MINOR-3 (RS2b guard): `assetEntriesOf` only scans the outer zip's `assets/`. A plain jar's `assets/` is caught; these are not: `assets/` inside an AAR's `classes.jar`/`libs/*.jar` (AGP merges those java resources into the APK), and data shipped as java resources outside `assets/` (e.g. OkHttp's JVM artifact keeps the PSL at `okhttp3/internal/publicsuffix/…`; that move would still trip the "entry gone" check). No gap today (APK checked). Robust form: check the built APK's non-dex/res entries against an allowlist.
- NIT: the verify_server_version refusal, the multi-signer refusal and the final clean-tree check have no test (deleting them would survive). The poll counts iterations, not wall time: if status hangs (5 s socket timeout) the 30 s wait can take about 3 min (probe F). "Running:" prints the file's version, not the version `status` reports. `scripts/release.sh`/`install.sh` are mode 0644, yet the README says to run `scripts/release.sh` directly; a bundle copied over FAT/phone storage loses +x (`bash install.sh` works). `JournalCommand` is exported, says `-n 50` while install.sh uses `-n 30`, and its comment claims install.sh uses it.
- NIT (step 2): the server binary is dynamically linked (cgo; GLIBC_2.34) with untrimmed debug paths (`/home/<user>/…`). For a public build use `CGO_ENABLED=0 -trimpath -s -w` (Q129 personal data).

VERDICT: PASS-WITH-FINDINGS (no BLOCKER, no MAJOR; MINOR-1 and MINOR-2 are cheap and worth doing before the first real install)
